# 検索・複数取得結果のコレクション契約

## 1. 目的、適用範囲、固定入力

この文書は、CLI（コマンドライン・インターフェース。端末から文字列で命令を渡す操作窓口）が**複数要素の結果**を返すときの共通契約を定める。ここでいうコレクションとは、同じ取得条件に一致した複数の要素を、一度に返せる結果のまとまりである。並び順、絞込み、ページ分割、継続取得、件数表現を共通化しない場合、コマンドごとに「次の結果」や順位の意味が変わり、Codex（文章の意味を判断して処理を進めるAI）も利用者も結果を安全に比較できない。

対象は、[公開コマンド台帳](./command-catalog.md)が複数要素を返し得ると定める、六つの `search-*` コマンド、`get` の履歴参照情報、`get-evidence` の複数根拠である。本書は検索条件が何を意味するか、各要素の本文、JSON（項目名と値で表すデータ交換形式）の具体的なキーや型、エラー番号・終了コード、契約版の表し方を決めない。それぞれ公開コマンド台帳、`L1-M2-S4` のJSON Schema、`L1-M2-S3` のエラー契約、`L1-M2-S5` の互換性契約の担当である。担当を分けるのは、同じ条件を複数の成果物で二重に決めて矛盾させないためである。

固定入力は、原典Issue #1、計画固定版Commit `9bf911b9122bf4ec51ec48312cc310de29bfcdff` のTask Map・接続台帳、[決定005](../../task-decomposition-decisions.md#決定-005-cli公開契約json-schemaの小分類)、および直接の先行成果物である公開コマンド台帳である。決定034〜037は、Taskの重複監査、接続台帳、単一Owner、leaf Issue化を承認した記録であり、本書のOwnerと後続への受渡し範囲を確認するために参照する。

## 2. 用語と変えない境界

| 用語 | この文書での意味 | 必要な理由と、似た語との違い |
| --- | --- | --- |
| 候補集合 | 検索条件に一致する可能性がある保存済み記録の集合。候補は真、既知、採用済み、矛盾成立を意味しない。 | 検索の機械的な取得結果を意味判断と取り違えないため。最終的に内容を採用する判断はCodexまたは利用者が行う。 |
| 要素 | コレクション内の一件。検索では候補、履歴では履歴参照、根拠取得では根拠と主張の結び付きである。 | 「検索結果」だけに限定すると履歴・根拠にも同じページ規則を適用できないため。各要素の本文の構造はJSON Schemaが定める。 |
| 絞込み | コマンドが定めた候補母集団から、呼出し元が指定した条件に一致しない要素を除く処理。 | 並び替えや件数上限とは異なる。絞込みは候補になるかを決め、並び替えは候補間の順序を決める。 |
| 順位値 | 検索条件に対する候補の相対的な並び順を決める数値。`score`（順位値）とも呼ぶ。 | 順位値は同一のコマンド、同一の正規化済み条件、同一の結果時点の中だけで比較できる。異なる検索方式、別の検索語、別時点の値を絶対的な品質や真偽として比較してはならない。 |
| 同順位 | 一次の並び替え基準が同じで、順位値だけでは順序を一意に決められない状態。 | 同順位を任意順にすると、次ページで重複・欠落が起きる。必ず後述の安定した識別値で順序を決める。 |
| ページ | 一つのコレクションを、上限件数までの連続した部分として返す単位。 | 全件を常に返す方法とは異なり、大きな結果でも応答サイズと処理時間を制限できる。ページ番号で任意位置へ飛ぶ機能ではない。 |
| 継続トークン | 同じ結果集合の次ページを取得するためにCLIが発行する不透明な値。一般にcursorとも呼ばれる。 | 呼出し元は値の構造を読み取ったり作り直したりしてはならない。ページ番号と違い、同順位の位置と取得時点を保持して重複・欠落を防ぐ。 |
| 総件数 | 現在の取得条件へ一致する全要素数。 | 今回返した要素数とは異なる。全件数の算出を要求すると重い検索を遅くし得るため、総件数は常に返す項目にしない。 |

コレクション契約は、CLIが保存済み記録を決定的に取得する境界にだけ適用する。CLIは、順位値を根拠の強さ、主張の真偽、利用者本人の知識、矛盾の成立、時間的な正しさへ変換してはならない。この禁止が必要なのは、取得の便利さをAIによる意味判断の代替にしないためである。

## 3. 共通の要求規則

### 3.1 候補母集団と絞込み

各コマンドは、公開コマンド台帳で定めた必須・任意・条件付き必須の入力だけで候補母集団を決める。`scope`、`relation_kinds`、`direction`、`as_of`、`product_version`、`revision_id`、`evidence_id` などの入力は、そのコマンドで定めた意味の絞込み条件であり、本書は意味を変更しない。呼出し元が未定義の任意属性、全文、順位値の範囲を指定して候補を追加で絞り込むことは許可しない。検索コマンドごとに利用可能な属性を勝手に増やすと、同じ公開契約を使う後続のSchemaと実装が一致しなくなるためである。

複数の絞込み条件を同時に指定した場合、要素は**すべて**の条件を満たすときだけ残す。同じ条件の値を複数指定できる入力では、公開コマンド台帳がその入力の意味を定める。たとえば `relation_kinds` は指定種別のいずれかに一致すればよいが、`scope` と時点条件を同時に指定した場合は両方を満たさなければならない。空文字列、空要素、同じ値の重複、またはそのコマンドで許可されない条件は要求として受理してはならない。失敗時の分類と伝達方法はエラー契約が定める。

### 3.2 ページサイズと順位上限

`page_size`（ページサイズ、1回のページ応答に含める最大要素数）は、全てのコレクションで省略又は指定できるページ分割の属性である。省略時は20件、許容値は1〜100の整数とする。0、負数、小数、101以上、数値以外は許可しない。`page_size`は候補母集団、絞込み、並び順、順位値、総件数を変えず、対象集合を何件ずつ返すかだけを決める。20件を既定にするのは、短い調査で一度に確認する量と、応答サイズ・処理時間の抑制を両立するためである。100件を上限にするのは、極端に大きい一回の応答が継続取得による負荷制御を無効にすることを防ぐためである。

`top_k`（トップ・ケー、絞込み後に順位順で並べた検索候補を上位何件まで対象集合に残すかを指定する順位上限）は、六つの `search-*` コマンドで省略又は指定できる、`page_size`とは別の属性である。省略時は100件、許容値は1〜100の整数とする。0、負数、小数、101以上、数値以外は許可しない。履歴参照と複数根拠は検索順位値を持たないため、`top_k`を指定してはならない。検索候補を上位範囲へ明示的に制限し、標準的な取得件数を明確にするため、この属性が必要である。

検索では、候補母集団を絞り込み、順位と同順位の規則で全体を一意に並べ、その先頭から最大`top_k`件を対象集合にする。その対象集合を、`page_size`件ずつ連続したページへ分けて返す。例えば`top_k=100`かつ`page_size=20`なら、上位100件だけを最大20件ずつ、最大5ページに分ける。`page_size`は一回に返す量、`top_k`はページング前に残す候補の上限であり、同じ値でも同じ意味ではない。この区別がないと、候補範囲を減らす指定と応答を分割する指定を混同して、結果の欠落又は継続取得の誤りを招くためである。

### 3.3 継続トークンと一貫した取得時点

最初のページは継続トークンを指定せずに要求する。応答の `has_more`（後続の有無）が真である場合に限り、次取得用の継続トークンを**必ず一つ**含める。`has_more` が偽である場合、継続トークンは存在してはならない。JSON Schemaが固定の項目として表現する場合だけはnull相当の値を許可するが、空文字列、前ページの値、次取得に使える値を置いてはならない。逆に、継続トークンが存在する応答で `has_more` を偽にしてはならない。この両方向の制約により、後続のデータ構造と実装は、`has_more` だけで継続取得の必要性を、継続トークンだけで次要求に使う値を一意に扱える。

呼出し元は受け取ったトークンを変更せず、同じコマンド名、同じ正規化済み検索条件、同じページサイズで次ページの要求へ渡す。最初のページで得たトークンを別コマンド、別条件、別ページサイズに使うこと、トークンと任意のページ番号を併用することは許可しない。

継続トークンは、少なくともコマンド、正規化済み条件、検索では`top_k`、並び順の最後の位置、結果を読み取った時点をCLI内部で結び付ける。不透明であるため、呼出し元は内部に含まれる識別子、順位値、時刻を前提にしてはならない。`top_k`を指定した最初の検索ページで得たトークンに対して、異なる`top_k`を指定することも許可しない。

成功したページの要素配列が0件なら、そのページは最終ページであり、`has_more=false`かつ継続トークンなし（固定項目ならnull相当）でなければならない。継続トークンを使った要求は、同じ取得時点に残る次の要素を返すので、空ページを返してはならない。残りがない場合は、当該トークンを新しい空ページへ進めず、期限切れ又は取得時点を維持できないトークンとして失敗させる。最終ページは返却件数が`page_size`未満である場合だけでなく、`page_size`と同数であってもよい。終端かどうかは返却件数ではなく、`has_more=false`かつトークンなしで判断する。これにより、空の初回結果、境界ちょうどで終わる結果、継続取得の終端を同じ規則で一意に扱える。

同一トークンによる再試行は、同じ要素、同じ順序、同じ `has_more`、同じ継続トークン有無のページを返す必要がある。空の初回最終ページを再試行した場合も、0件、`has_more=false`、継続トークンなしを返す。これにより通信失敗後の再試行でページを飛ばしたり、終端ページを途中ページとして扱ったりしない。トークンが期限切れ、改変済み、別要求用、または結果時点を維持できない場合は、古いトークンを新しい検索として解釈してはならない。呼出し元はトークンなしで最初から取得をやり直す。具体的な失敗コードと終了コードはエラー契約の担当である。

### 3.4 並び順、順位値、同順位

検索コマンドの一次順序は順位値の降順（大きい値を先）とする。順位値が同じ候補は、候補の永続的な識別子を昇順で比較して順序を一意にする。`search-related` は候補主張の識別子、`search-contradictions` と `search-temporal` も比較対象となる候補主張の識別子を二次順序に使う。識別子が同じ候補を複数回返すことは許可しない。

順位値は、検索の候補選択に利用した有限の数値でなければならない。値が存在しない、非数値、無限大、未定義の値は許可しない。同じ検索要求内では、順位値が等しいときだけ同順位とする。表示用に丸めた値が同じでも内部の順位値が異なる場合は同順位ではない。これにより、表示の丸めによって継続トークンの境界が変わることを防ぐ。

`search-related`では、同一の相手側主張を表す結果要素は必ず1件に集約する。集約した要素は、条件に一致した保存済み関係を**関係対応一覧**（相手側主張へ到達した関係を並べた一覧）として、関係識別子ごとに重複なく保持する。関係対応一覧は関係識別子の昇順で安定して並べる。関係識別子は関係一件を一意に表す永続的な値であり、同じ識別子の関係は同一の対応として一件へ統合するため、同値同士に追加の順序はない。関係の種別、向き、又は到達経路が異なっても識別子が異なれば別の対応として一覧に残し、相手側主張を別の結果要素にしてはならない。具体的な一覧のJSONキーと各対応の型はJSON Schemaの担当が定める。

この集約は、複数関係で同じ相手側主張へ到達した場合の重複返却を防ぎつつ、その主張がどの関係で一致したかを失わないために必要である。検索結果の順位とページ境界は、集約後の相手側主張要素に対して、既存の順位値降順・相手側主張識別子昇順で決める。関係対応一覧の件数や並びは結果要素を増減させず、識別子昇順で再現できるため、同じ条件・取得時点・継続トークンによる再試行でも、ページの境界と要素内の関係情報を同じように再現できる。

履歴参照と根拠のコレクションには順位値を含めてはならない。順位値の代わりに、履歴参照は改訂版の新しい順、同じ改訂時点なら改訂識別子の昇順で並べる。複数根拠は主張へ結び付けた時点の新しい順、同じ結び付け時点なら根拠識別子の昇順で並べる。これは「検索上の近さ」と、保存済みの履歴・根拠を確認する時系列を混同しないためである。

### 3.5 件数表現

各ページは、返した要素の配列、返却件数、後続の有無、必要な場合だけ次ページ用の継続トークンを含む。返却件数はそのページの配列の要素数と必ず一致し、重複要素を数えてはならない。0件は有効な成功結果であり、検索条件に一致する保存済み記録がこの結果時点にはなかったことだけを表す。0件を、利用者が知らないこと、主張が偽であること、根拠が存在しないことへ読み替えてはならない。

総件数が取得時点で負荷を増やさず正確に算出できる場合だけ、CLIは正確な総件数を補助情報として返してよい。総件数を返す場合は、ページをまたいでも同じ取得時点の値でなければならない。正確に算出できない、または返すことで検索の実用性を損なう場合は、総件数を省略する。推定値、丸め値、上限で打ち切った値を総件数として返してはならない。呼出し元は `has_more`（後続の有無）と継続トークンを使って全件取得の可否を判断する。

## 5. 後続Taskへの受渡し

`L1-M2-S4` は本書を入力に、各コレクションの要求・応答をJSON Schemaへ具体化する。具体化の際、全コレクションの`page_size`（既定20、1〜100）と検索だけの`top_k`（既定100、1〜100）が別属性であり、`top_k`で限定した集合を`page_size`でページ分割すること、継続トークンの不透明性、返却件数と配列長の一致、`has_more=true`と継続トークンの存在、および`has_more=false`と継続トークンの不在又はnull相当が一対一に対応すること、空成功ページは最終ページであること、検索だけに順位値を置くこと、総件数が任意で推定値を禁止することを変更してはならない。JSONのキー名、数値・文字列の機械表現、共通応答の入れ子構造はS4が決める。

このTaskの成果物を渡せることと、後続Taskを直ちに開始できることは異なる。#36は本書に加えて#35のエラー契約を、#38は#35から#37までの全CLI契約成果物を必要とする。したがって本書の完成だけを、後続全体の着手可能条件として扱ってはならない。
