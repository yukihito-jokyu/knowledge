# 更新対象探索・意味比較設計書

## 1. 目的、前提、担当境界

Knowledge Update（利用者本人が示した知識の候補を、既存の知識記録へ安全に反映する処理）は、Candidate（候補）が来たからといって直ちに新しい命題を作成してはならない。まず既存の `KnowledgeAssertion`（利用者本人が知っているかを一件ずつ評価する具体的な命題）を探索し、候補と既存記録の意味・適用範囲・時点・根拠を比較する。本書は、この更新対象を特定するまでの手順を定める。不要な重複登録を防ぎつつ、訂正や製品版差を同一性として潰さないために必要である。

この文書でいう「意味比較」は、文字列や検索順位だけで同じと決めず、何を主張するか、どの条件で成り立つか、いつ・どの製品版に適用するか、利用者本人のどの原文を根拠にするかを読む判断である。Codexがこの意味判断を行い、CLI（コマンドライン処理）は指定された条件に一致する保存済み候補の取得と、後続Taskが決める保存を行う。この分離が必要なのは、検索結果を真偽・同一性・利用者本人の知識状態の結論にすり替えないためである。

固定入力は、原典 Issue #1、固定計画 Commit `9bf911b9122bf4ec51ec48312cc310de29bfcdff`、`L3-M1-S3` の [Candidate Markdown・候補なし・入力不足の引渡し契約](../knowledge-acquisition/candidate-markdown-contract.md)、および L1 の論理モデル・CLI公開契約である。Candidateの受入可否は `L3-M2-S1`、4更新操作と更新しない判断は `L3-M2-S3`、CLI呼出しの要求・応答・失敗の対応は `L3-M2-S4` が単一Ownerである。本書はそれらを選び直さない。

## 2. 用語と比較単位

| 用語・識別名 | この文書で表すもの | 必要な理由と、似たものとの違い |
| --- | --- | --- |
| Candidate（候補） | Acquisitionが正規化して渡す、利用者本人の原文・命題・検索用索引語・適用範囲・時点・根拠を持つ未保存の比較入力 | 保存済み命題でも、既知性の結論でもない。比較前に新規作成と扱うと重複を防げない。 |
| `KnowledgeAssertion`（知識判定用の命題） | 保存済みの、利用者本人が知っているかを一件ずつ評価する対象 | Candidateの正規化済み命題と比較する相手である。検索用索引語だけでは主張内容を比較できない。 |
| `Concept`（検索用索引語） | 命題に関係する語句、別名、API名などの検索入口 | 命題そのものでも知識状態でもない。索引語の一致は候補発見の手掛かりであり、意味的同一性の証明ではない。 |
| Scope（適用範囲） | 技術分野、プログラミング言語、製品・機能など、命題が成り立つ条件 | 同じ文でも対象が異なれば別の評価対象になり得る。未記載は全範囲に通用する意味ではなく、条件を観測していない意味である。 |
| 時点・製品版情報 | 観測時点、有効期間、対象製品版など、命題内容がいつ・どの版で成り立つかを示す情報 | 保存操作の時刻や検索時刻とは別である。差を無視すると古い内容を矛盾、又は同一内容として誤る。 |
| Evidence（採用済みの根拠） | 利用者本人が示した原文・コード・訂正などを、命題の根拠として採用した記録 | Candidate内の根拠候補とは別であり、同じ出典断片を二重に保存しない比較が必要である。Evidenceがないことは利用者本人の不知ではない。 |
| 関連命題 | 同じ結論ではないが、前提・構成要素・因果・補足などとして比較に役立つ既存命題 | 同一命題と区別する。関連があるだけで既存命題へ根拠を付け足すと、異なる評価対象を混同する。 |
| 比較十分性 | 候補を新規・既存同一・訂正/置換の候補などへ安全に引き渡すのに必要な探索と取得が終わった状態 | 検索結果が0件だったことではない。未観測を未知、未検索を新規と誤判定しないために必要である。 |

## 3. 入力の検査と探索計画

本書が開始できるのは、受入可と判定済みの `result_kind: candidate` の各Candidateだけである。`no-candidate` は正常に候補が無かった結果、`input_insufficient` は安全な評価ができない結果であり、いずれも比較対象を作らない。これらを新規命題として探索すると、候補なし・入力不足を利用者本人の知識として保存する事故が起きる。

Candidateごとに、以下を比較メモへ分けて記録する。比較メモは本書が定める判断材料であり、後続 `L3-M2-S3` が決定文書の形式を定めるまで、外部Markdownの項目名やCLI要求の形式を固定しない。

| 比較メモの要素 | 意味 | 必要な理由・許可条件 |
| --- | --- | --- |
| Candidate識別 | Episode識別子、Candidate番号、正規化済み命題 | 同じEpisode内の複数候補や後続判断を取り違えないため必須。保存用IDを新たに発行してはならない。 |
| 主張の核 | 主語、述語、対象、因果・否定・条件を含む、候補が何を主張するか | 語句だけが似た別命題を同一と誤ることを防ぐ。原文の要約を根拠へ置き換えない。 |
| Scopeと時点 | 観測済みの適用範囲、有効期間、製品版、観測時点 | 比較対象の条件をそろえるため必要。未観測の値を現在・無期限・特定版として補完しない。 |
| 検索用表現 | 命題本文、Conceptの代表表記・別名、原文に現れる重要語、条件を保った言い換え | 表記揺れで既存命題を見逃さないため必要。検索用の言い換えを正式命題や保存対象にしてはならない。 |
| 取得済み事実 | 候補として見つけた命題、各命題の現在版・必要な履歴、根拠、関係、時点差 | 検索候補と実際の比較材料を区別するため必要。検索順位や類似度だけを結論の根拠にしない。 |
| 未比較範囲 | 未取得の根拠、解決不能な時点・Scope、失敗した探索と影響 | 比較を完了と偽らず、後続が安全に非永続化又は追加調査を選べるようにするため必須。 |

探索は次の順で行う。ただし、固定回数の検索、順位閾値、索引方式、CLIの具体的な要求形式は本書で決めない。これらはL1公開契約とL2検索基盤の担当であり、固定すると後続の実装選択を拘束するためである。

1. Candidateの正規化済み命題を、同じScopeを指定できる場合はそのScopeと共に探索する。まず同じ表現で記録された命題を見つけ、不要な意味的拡張を避けるためである。
2. CandidateのConcept、別名、原文で確認できる重要語を用いて探索する。表記揺れ、略称、API名の差で同一又は関連命題を見落とさないためである。
3. 主張の核を保った言い換えで意味的な候補を探索する。文字列が異なる同じ結論を発見するためであり、意味的な近さだけを同一性の結論にしてはならない。
4. 直接候補が十分でない場合、Candidateの前提・構成要素・因果関係を分けて関連命題を探索する。全体の結論を既に知っているかと、部品だけを知っているかを区別するためである。
5. 比較対象ごとに現在内容、必要な改訂履歴、Evidence、明示関係を取得する。候補一覧だけでは根拠の重複、訂正、適用条件を確認できないためである。
6. 内容又は条件が近い対象について、矛盾候補と時点・製品版差の候補を探索し、必要な根拠を取得する。相反する結論と、異なる時点で両立する結論を分けるためである。
7. 第5章の比較観点が満たされ、未比較範囲が結論を変えないかを判定する。不足する場合は新規作成・根拠追加・訂正・置換を選ばず、未完了として後続へ渡す。

L1の公開CLI契約では、文字列、意味、Concept、関係、矛盾候補、時点候補の探索と、命題・根拠の取得が用意される。各結果はすべて「候補」である。CLIは、真偽、既知性、矛盾の成立、時点上の正しさ、意味的同一性を判定しない。したがって、検索種類を使わなかった場合も「使わなくてよいと判断した比較観点」と理由を比較メモへ残す。

## 4. 取得後に比較する観点

各Candidateと既存 `KnowledgeAssertion` の組合せを、少なくとも次の観点で読む。一つの検索結果から複数の比較候補が出ても、候補ごとに独立して記録する。複数候補を一件へまとめると、一方との同一性と他方との矛盾を同時に追跡できなくなるためである。

| 比較観点 | 同じと扱うために確認すること | 同じと扱ってはならない条件 | 必要な理由 |
| --- | --- | --- | --- |
| 主張の核 | 同じ対象について、同じ結論・因果・否定・条件を主張している | 語句又はConceptだけが一致する、片方がより広い/狭い結論、前提又は例外が異なる | 文字列の近さによる重複登録と、別命題の誤統合を防ぐ。 |
| Scope | 観測済みの範囲が同じ、又は片方の範囲内で同じ主張として比較できる | 製品、言語、機能、業務領域が異なる。未観測を全範囲として補う | 同文でも適用対象が違えば別の知識評価が必要になる。 |
| 時点・製品版 | 同じ時点・版に対して同じ内容を表す | 有効期間又は対象版が異なる。片方だけが未観測で、差を解消できない | 古い情報と新しい情報の差を、現在の矛盾又は無条件の同一性にしない。 |
| 根拠の同一性 | Candidateの原文断片と既存Evidenceが、同じ出典・位置・内容照合値又は再読で同一と確認できる | 同じEpisode、同じ話題、似た文であるだけ。原文又は位置を再確認できない | 同じ観測を複数の根拠として数え、状態計算を歪めることを防ぐ。 |
| 訂正・挑戦 | Candidateの原文が既存結論を明示的に訂正・反証・条件付きにしているかを、両方の根拠で確認する | 単なる質問、AIの説明、条件・時点の差だけ。矛盾候補一覧だけ | 利用者本人の訂正を失わず、候補検索を矛盾の確定と誤認しない。 |
| 関係 | 前提、構成要素、因果、補足など、既存命題との明示的な関係を確認する | 関連語があるだけ、又は関係の向き・種類を確認できない | 部分知識と全体結論を区別し、必要な追加探索を決められる。 |

## 5. 比較結果の分類

この分類は探索・比較の結果を後続へ渡すためのものであり、`known`、`partially_known`、`inferable`などの利用者本人の知識状態を判定するものではない。その8状態の評価はL4のKnowledge Searchの責務である。また、分類は `create`、`attach-evidence`、`revise`、`supersede` の選択結果でもない。操作選択は `L3-M2-S3` が、本書の比較結果とL1更新不変条件を入力に決める。

| 分類 | 意味と該当条件 | 該当しない条件 | 後続へ渡す最小の比較事実 |
| --- | --- | --- | --- |
| `equivalent_existing`（既存同一候補） | 主張の核、Scope、時点・版の比較で、Candidateと既存命題が同じ評価対象だと説明できる | 語句だけが似る、条件が未比較、時点差・例外差を未解決 | 対象命題ID・改訂版、同一とした各観点、比較したEvidence、根拠重複の有無 |
| `related_not_equivalent`（関連するが別命題） | 前提・構成要素・因果などの関係はあるが、同じ結論・条件ではない | 「関連するから既存命題へ根拠を追加する」という操作結論 | 関連命題ID、関係の種類と向き、異なる主張又は条件、残る探索範囲 |
| `candidate_new`（新規候補） | 十分な探索と取得をしても、同じ評価対象の既存命題を確認できない | 検索0件だけ、検索障害、未取得の有力候補が残る場合 | 実行した探索表現と範囲、取得候補、同一でない理由、未比較範囲が結論へ影響しない根拠 |
| `correction_or_conflict_candidate`（訂正又は競合候補） | 同じ又は重なる対象で結論が両立しない可能性を、Candidateと既存Evidenceから確認した | 矛盾候補検索のヒットだけ、時点・版の違いだけ、質問だけ | 相手命題ID、対立する主張・条件、各Evidence、時点・Scope比較、未解決の点 |
| `temporal_or_version_variant`（時点又は版が異なる候補） | 内容の差を時点・有効期間・製品版の違いとして説明できる、又はその差の確認が必要である | 同じ時点・版の矛盾を時間差として隠す場合 | 相手命題ID、各時点・版、同じ点と異なる点、確認できない値 |
| `duplicate_evidence_candidate`（根拠重複候補） | Candidateの原文断片が既存Evidenceと同じ観測だと確認できた | 同じ話題、同じEpisode、同じ人が別時点で行った別の説明 | 相手Evidence ID、出典・位置・内容照合の一致根拠、対応する命題ID |
| `comparison_incomplete`（比較未完了） | 取得失敗、Scope・時点・根拠の解決不能、未取得候補などにより、上記を安全に選べない | 単なる候補0件、既に比較した無関係候補 | 未完了の観点、失敗又は欠落した入力、ここまでの取得事実、結論へ与える影響 |

一つのCandidateは、`equivalent_existing` と `duplicate_evidence_candidate`、又は `related_not_equivalent` と `temporal_or_version_variant` のように複数分類を持ち得る。ただし、同一の既存命題との主張の核について、`equivalent_existing` と `candidate_new` を同時に付けてはならない。対象・条件が異なる複数命題なら、比較対象を分けて両方を記録する。

## 6. 比較十分性と安全な停止

比較が十分であるためには、少なくとも次を満たす必要がある。

- Candidateの命題、観測済みScope・時点、利用者本人の原文と出典位置を比較対象として確認している。これがなければ、何を比較したか追跡できない。
- 直接表現、Concept、意味的言い換えの探索を検討し、使わない探索種類には不要と判断した理由を残している。全種類の機械的実行は不要だが、表記揺れを理由なく除外しないためである。
- 有力な既存候補は、一覧だけで終わらせず、命題内容、必要な履歴、Evidence、関係、時点・版を取得している。候補一覧は意味比較の証拠にならないためである。
- 矛盾又は時点差があり得る候補は、それぞれを別の比較観点として確認している。訂正の必要性と旧版の違いを混同しないためである。
- 取得失敗又は未取得範囲があるとき、その範囲が比較結論を変えない理由を説明できる。説明できなければ `comparison_incomplete` とする。

探索の予算、再試行回数、再起動、別Skillへの振り分け、Workflowを止めるか続けるかはL5が決める。本書は比較未完了の事実と影響を報告するだけである。比較未完了を「新規」と扱うことも、CLIに追加の意味判断を委ねることも禁止する。

## 7. 操作選択・CLI・評価との境界

| 境界 | 本書が渡すもの | 本書が決めないもの | 分離が必要な理由 |
| --- | --- | --- | --- |
| `L3-M2-S3` 更新判断 | 分類ごとの比較事実、対象ID、根拠重複、未比較範囲 | 4更新操作又は非永続化の選択、Decision Markdownの形式 | 比較と副作用の選択を分け、検索結果だけで保存を決めない。 |
| `L3-M2-S4` CLI連携 | 必要な探索・取得の順序と、候補結果が結論ではない境界 | コマンド要求、応答、失敗形式、再試行可否の引渡し | 公開CLI契約を再設計せず、意味判断と機械実行を混同しない。 |
| `L2-M2-S1` 検索基盤要件 | 文字列・意味・Concept・関係・矛盾候補・時点候補、命題・根拠取得が必要な理由 | 索引方式、順位、閾値、再構築、技術選定 | 更新用探索要求を検索基盤の入力にしつつ、方式選定を先取りしない。 |
| L4 Knowledge Search | 「候補」から更新対象を特定する比較観点 | Article Claimについての8状態評価、Search Trace、読書価値判断 | 更新対象の同一性と、利用者本人が記事内容をどこまで知るかは別の問いである。 |
| L5 Workflow | `comparison_incomplete`を含む比較結果と未比較範囲 | 起動、再試行、停止、再開、複数Candidateの実行制御 | 意味結果を作るSkillと、処理順・副作用を管理する親処理を分離する。 |
| L6 評価 | 比較手順の意味上の不変条件 | Fixture、Dataset、Harness、シナリオ評価、合否Report | 設計本文に共有評価資産を重複して所有しない。 |

## 8. 直接の後続Taskへの引継ぎ

| 直接の後続Task | 今回渡す成果物 | 受渡し可否 | 後続Taskが今すぐ開始できるか |
| --- | --- | --- | --- |
| `L2-M2-S1` | 技術非依存の更新用探索要求。必要な候補探索、命題・根拠取得、矛盾候補と時点候補の区別、検索結果が結論ではない境界 | 渡せる。検索・索引要件と正本設計Review Gate基準の入力にできる | いいえ。L1、L4-M2-S1など、#49固有の着手依存も必要である。 |
| `L3-M2-S3` | Candidateと既存命題の比較分類、対象ID、根拠重複、比較未完了の報告条件 | 渡せる。4更新操作又は非永続化の選択材料にできる | いいえ。L3-M2-S1とL1-M1-S4など、#74固有の着手依存も必要である。 |
| `L3-M2-S4` | 探索・取得の意味上の順序、候補結果と意味結論の区別、比較結果をCLI操作へ変換する前提 | 渡せる。CLI利用・結果引渡しの詳細設計へ参照できる | いいえ。#75はL1-M2で着手できても、本書と#74を含む完了・Merge依存の後に確定する。 |

「渡せる」は、この設計書を後続が読取り入力として利用できることを意味する。「今すぐ開始できる」は、後続自身のすべての着手依存・Gate・統合状態を満たす別の判定である。一つの成果物が完成しても後続全体が開始可能とは限らないため、両者を分ける。

## 9. 完全性確認

- Candidateを直ちに新規作成と見なさず、既存命題、関連命題、根拠、訂正、時点・版を段階的に比較する。
- 文字列・Concept・意味的近さ・矛盾候補・時点候補を、いずれも探索の手掛かりとして扱い、CLI又は検索順位による結論にしない。
- `no-candidate`、`input_insufficient`、比較未完了を、利用者本人の未知又は新規命題として保存しない。
- 同一性、関連、根拠重複、訂正・競合、時点・版差を別の観点として記録し、後続の更新選択と評価責務を混同しない。
- L2-M2-S1、L3-M2-S3、L3-M2-S4へ必要な入力を渡し、索引方式、更新操作、CLI要求・応答、Workflow制御、共有評価資産を本書から除外する。
